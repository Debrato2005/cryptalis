# Product objective ledger

All **34 objectives** remain required for the first production release. This is
the single work ledger. [Status](status.md) owns executed results and release
gates; [compatibility](compatibility.md) owns the admitted operation matrix.

## Status vocabulary

| Label | Meaning |
|---|---|
| SPECIFIED | Required; implementation is absent. |
| IMPLEMENTED | Product source exists; acceptance is incomplete. |
| PARTIAL | Some of the objective is implemented or verified; listed gaps remain. |
| VERIFIED, bounded | Executed evidence supports only the stated scope and revision. |
| BLOCKED | A named external prerequisite is unavailable. |
| ONGOING | Continuing evidence/research work, not a completed release objective. |
| QUALIFIED | All applicable acceptance criteria and release gates pass; no current objective has this release claim. |
| UNKNOWN | Required evidence is missing; never a pass. |

Do not measure completion by commits or test totals. Preserve failed and skipped
evidence. Update a row when its implementation, proof, gap or next action changes.

## Next critical path

Ordered by the largest remaining gap against the [18 requirements](requirements.md):

1. **Search and types (requirements 5, 6).** Range and sorting work on integers, dates and naive timestamps.
   Naive timestamp and finite numeric storage are implemented. Timezone-aware timestamps, other precisions, numeric search/arithmetic/nonfinite values, text search and JSON remain unadmitted. Choose each
   representation by what a database dump reveals, using the
   [prior-art table](prior-art.md#query-construction-comparison). Refusal alone is not completion.
2. **Native behavior (requirement 6).** Widen the admitted ORM, type and DML matrix with
   real application oracles.
3. **Performance (requirement 14).** The current profile fails the added-p95 read targets.
   Optimize from profiles and preserve the recorded failures.
4. **Operations (requirements 7, 11, 13).** Versioned upgrades, deployment fencing,
   provider identity, audit, HA, retained-copy inventory, controlled key retirement and
   tenant onboarding without a global writer pause.
5. **Assurance (requirement 15).** Independent crypto, security and database review, and
   release provenance. Live cloud accounts are needed only for selected provider cells.

The [build guide](build-guide.md) owns the execution sequence and verification
commands. [Historical imports](history/imports-2026-10.md) retain provenance.
